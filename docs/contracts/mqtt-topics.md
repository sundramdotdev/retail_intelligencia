# docs/contracts/mqtt-topics.md — MQTT Topics & Protocol Specification

> **EDGE-TO-CLOUD TELEMETRY TRANSPORT PROTOCOL**
> 
> This document defines the formal MQTT namespace, topic taxonomy, payload rules, Quality of Service (QoS) levels, message retention policies, and security constraints governing edge device communications.

---

## 1. Global Namespace Taxonomy

To enforce multi-tenant isolation, clean operational segmentation, and deterministic routing, all MQTT topics must follow the strict prefix hierarchy:

```text
retail/{environment}/{storeId}/{deviceId}/{channel}
```

### Parameter Definitions
* `{environment}`: Operational environment identifier (`prod`, `staging`, `dev`).
* `{storeId}`: Unique store identifier (e.g., `store_001`).
* `{deviceId}`: Unique physical edge appliance identifier (e.g., `edge_001`).
* `{channel}`: Functional message channel (`events`, `heartbeat`, `health`, `config`, `control`).

## 3. Topic Specifications & Payloads

### 3.1 Telemetry Events Channel
* **Topic**: `retail/{env}/{storeId}/{deviceId}/events`
* **Purpose**: Primary channel for transmitting real-time operational intelligence events generated by the edge rule engine.
* **QoS Level**: **1 (At Least Once)**. Guarantees that the MQTT broker acknowledges receipt via `PUBACK`. If no `PUBACK` is received within the timeout window, the edge client re-sends the event.
* **Retain Flag**: `false`. Real-time events are transactional streams and must not be retained on the broker.
* **Payload**: Complete canonical `RetailEvent` JSON (see [docs/contracts/retail-event-contract.md](file:///c:/hackathon/retail_intelligencia/docs/contracts/retail-event-contract.md)).

---

### 3.2 Heartbeat Channel
* **Topic**: `retail/{env}/{storeId}/{deviceId}/heartbeat`
* **Purpose**: High-frequency, low-overhead liveness ping used by the backend to monitor network connectivity and calculate instantaneous fleet uptime.
* **Cadence**: Published every 30 seconds.
* **QoS Level**: **0 (At Most Once)**. Missing an occasional heartbeat is acceptable; network bandwidth must not be saturated with re-transmissions.
* **Retain Flag**: `false`.
* **Payload Schema**:
  ```json
  {
    "deviceId": "edge_001",
    "storeId": "store_001",
    "timestamp": "2026-09-05T10:30:00Z",
    "uptimeSeconds": 864200,
    "status": "HEALTHY",
    "schemaVersion": "1.0"
  }
  ```

---

### 3.3 Device Health Channel
* **Topic**: `retail/{env}/{storeId}/{deviceId}/health`
* **Purpose**: Detailed hardware and subsystem telemetry, reporting CPU/GPU utilization, thermal readings, memory consumption, storage space, and camera stream health.
* **Cadence**: Published every 60 seconds or immediately upon state change (e.g., camera disconnect or GPU overheating).
* **QoS Level**: **1 (At Least Once)**.
* **Retain Flag**: `true`. The broker retains the latest health state so new backend consumers immediately receive the current hardware status upon subscription.
* **Payload Schema**:
  ```json
  {
    "deviceId": "edge_001",
    "storeId": "store_001",
    "timestamp": "2026-09-05T10:30:00Z",
    "metrics": {
      "cpuPercent": 42.1,
      "gpuPercent": 78.5,
      "gpuTempCelsius": 68.2,
      "ramUsedMb": 5120,
      "ramTotalMb": 8192,
      "diskFreeMb": 42100
    },
    "cameras": [
      { "cameraId": "cam_01", "status": "ONLINE", "fps": 15.0, "dropRate": 0.0 }
    ],
    "models": [
      { "modelId": "person-detector-yolov8", "status": "RUNNING", "latencyMs": 18.2 }
    ],
    "schemaVersion": "1.0"
  }
  ```

### 3.4 Configuration Push Channel
* **Topic**: `retail/{env}/{storeId}/{deviceId}/config`
* **Purpose**: Transmits store zone geometries, camera RTSP credentials, detection thresholds, and model execution profiles from cloud to the physical edge appliance.
* **Direction**: Cloud Backend ──► Edge Appliance.
* **QoS Level**: **1 (At Least Once)**.
* **Retain Flag**: `true`. When an edge node boots or reconnects, it immediately receives its latest configuration from the broker.
* **Payload Schema**:
  ```json
  {
    "configVersion": "2026.09.05.1",
    "timestamp": "2026-09-05T10:00:00Z",
    "cameras": [
      {
        "cameraId": "cam_01",
        "streamUrl": "rtsp://192.168.1.120:554/live/ch0",
        "fps": 15,
        "width": 1920,
        "height": 1080
      }
    ],
    "zones": [
      {
        "zoneId": "zone_checkout_01",
        "cameraId": "cam_01",
        "type": "QUEUE",
        "polygon": [[120, 450], [380, 450], [400, 850], [100, 850]],
        "thresholds": {
          "queueLimit": 6,
          "durationSeconds": 60
        }
      }
    ]
  }
  ```

---

### 3.5 Remote Control Channel
* **Topic**: `retail/{env}/{storeId}/{deviceId}/control`
* **Purpose**: Sends administrative commands to the edge device, such as restarting an inference worker, refreshing camera connections, or updating model weights.
* **QoS Level**: **2 (Exactly Once)**. Control actions must execute precisely once without duplicate invocations.
* **Retain Flag**: `false`.
* **Payload Schema**:
  ```json
  {
    "commandId": "cmd_01J98X...",
    "command": "RESTART_CAMERA_STREAM",
    "target": "cam_02",
    "timestamp": "2026-09-05T10:31:00Z",
    "issuedBy": "usr_mgr_admin_01"
  }
  ```

## 4. Transport Security & Access Control (ACL)

1. **Mandatory TLS**: All production MQTT connections must use TLS 1.3 over TCP port 8883. Unencrypted communication over port 1883 is disabled in production.
2. **Mutual TLS (mTLS)**: Edge appliances authenticate via unique client X.509 certificates issued during hardware provisioning.
3. **Strict Broker ACLs**:
   * An edge node authenticated as `edge_001` in `store_001` is strictly authorized to publish **only** to `retail/{env}/store_001/edge_001/*`.
   * An edge node is strictly forbidden from publishing or subscribing to topics belonging to any other `storeId` or `deviceId`.
   * The backend gateway holds administrative subscription credentials to `retail/+/+/+/events` and `retail/+/+/+/health`.
