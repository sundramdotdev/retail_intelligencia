# Dwell Intelligence

## Purpose
Detects when a customer spends significant time in a high-value zone (e.g. premium electronics), which may indicate high purchase intent or a need for staff assistance.

## Input
- `ZONE_ENTERED`, `ZONE_CHANGED`, and `ZONE_EXITED` observations generated by Phase 2.

## Formula
The rule engine tracks independent timers for each `track_id` in the zone.
`dwell_duration = context_timestamp - entry_timestamp`

## Triggers
- **ZONE_DWELL**: When a track remains continuously in the zone and `dwell_duration >= min_duration_seconds`.

## Constraints & Edge Cases
- Timers are dynamically created upon entry and destroyed upon exit/change.
- If a track is lost by the upstream tracker, the corresponding timer is cleaned up in the next evaluation cycle.
- The rule emits exactly one `ZONE_DWELL` event per track per zone session.
- Respects `cooldown_seconds` on a per-track basis to avoid multi-firing.
