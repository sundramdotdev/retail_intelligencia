# Retail Rule Engine

The Retail Rule Engine evaluates visual observations generated by Phase 2 and translates them into actionable business events. 

## RetailContext
Every evaluation cycle, the vision pipeline yields a `RetailContext`. This context represents a snapshot containing:
- Timestamp (float)
- Configured Device and Camera IDs
- Current active visual `TrackedObject`s
- Raw state change `Observation`s (e.g. `ZONE_ENTERED`)

## Rule Orchestration
The `RetailIntelligenceEngine` stores a registry of active rules configured in `edge.yaml`. Every configured rule (Queue, Shelf, Dwell, Traffic) is evaluated independently on the context.

## State and Debouncing
To prevent duplicate event generation and jitter (e.g., a person flickering across a boundary line), the engine injects:
- **StateManager**: A lightweight, in-memory key-value store to retain rule state (e.g. `HIGH` vs `NORMAL`).
- **Debouncer**: An engine abstraction to provide conditional persistence ("must be true for N seconds") and cooldown ("do not trigger again for N seconds").

## Output
When a rule fully triggers, it returns a `RetailEvent` structured according to the canonical Phase 0 contract using the `RetailEventFactory`, including strict monotonic ULIDs and UTC timestamps.
